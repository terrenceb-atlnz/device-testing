**The headline contrast.** By cache read this was the cheapest-but-one case of the ten in the
campaign (7.67 M of 126.0 M), yet it read back 51.7 kB of tool output -- the third highest of
the ten. The two numbers point in opposite directions, and the reason is worth carrying
forward: *cost tracks accumulated context multiplied by the number of API calls, not the
volume of output*. This case averaged 153 k of context per call against the campaign's 210 k,
because it ran as one near-linear pass -- 52 tool calls, each bench command writing its full
output to `work/` and reading back only a `grep -E '^(---|RESULT|GRADE|rc=)'` slice of it, and
no large document re-read after the gates. Reading a lot *once*, in small per-call slices, is
cheap. Re-reading a little, many times, is not.

## Accuracy risks

1. **The diagram's `port1.0.10` label is an inference, not a reading.** `T43870.log` line 115
   and line 145 call the measuring leg "default VLAN 1, no per-port configuration" / "copper,
   untagged VLAN 1". Confirmed here: `port1.0.10` appears nowhere in `swi_d.cfg`, nowhere in
   `work/pre-u2.log` and nowhere in `work/post-u2.log`. The claim rests on the *absence* of a
   stanza plus the address sitting on vlan1 -- there is no `switchport access vlan` line
   anywhere in the evidence. `bench-state.md` proves the cable (`eth3 up swi_d:port1.0.10`) but
   says nothing about VLAN membership. **Closes with:** one
   `show running-config interface port1.0.10` (or `show interface port1.0.10 switchport`) in
   the next run, saved to `work/`. This does not touch the verdict: every graded leg was taken
   over a path with a live ICMP control in the same leg.
2. **The STEP 5 walk and the STEP 11 decode survive only as transcription.** The log's STEP 5
   quotes "32 varbinds" with six sampled, and STEP 11 quotes the decode. Both dumps *do* exist
   in full -- `work/s5-steps4-5.log` (3,711 B; the permitted walk is 32 varbind lines plus a
   closing `Timeout: No Response`, so the log's count is exact) and `work/s11-wire-decode.log`
   (3,707 B, 18 decoded messages) -- but `/create-logs` deletes `work/` at the end of this
   step, after which the log's transcription is the only durable record. **Closes with:** the
   next run either quotes both dumps in full in the final log, or the Test Engineer agrees a
   named evidence file is kept out of the `work/` deletion. Verified here before deletion: the
   transcription matches the dump.
3. **The STEP 11 capture itself is already gone.** The pcap was left on the box at
   `/tmp/ckt1406/snmpwire.pcap` (#53, #57) and never copied into the repo; `/tmp` on tb277 is
   tmpfs, cleared by the reboot the box has since had. The decode in the log is now the only
   record of the encryption claim. **Closes with:** `tb get`-ing the capture into `work/` and
   chowning it, as memory `tcpdump-nfs-root-squash-capture` requires; the same memory warns
   that a size read before the writer exits reads zero, so check the size after `tb capture`
   returns.
4. **O-9 is an accuracy risk in the case text, and the next run will hit it again.** The
   authored precondition creates group `ADMINadminADMINadmin` reading view
   `MOSTmostMOSTmostMOST` but never defines that view, and step 6 types the OID
   `1.3.6.1.1.2.1.1.5`, which is not a path to sysName. Applied verbatim (#44-#45) every read
   is refused and the case reads as a product failure. **The one line that fixes the run:**
   after the authored block, send
   `snmp-server view MOSTmostMOSTmostMOST 1.3.6.1.2.1.1 included`
   and read step 6's OID as `1.3.6.1.2.1.1.5`. **The fix that stops it recurring** is in Zephyr,
   not on the bench: AWPTCM-T43870's precondition needs that line and the OID typo corrected.
5. **F-12 carries no accuracy risk.** The verdict rests on measured output: five matched
   GetNext legs at 5 s timeout with up to 3 retries (#50), two of them inside the view
   returning values, the boundary and out-of-view ones returning nothing at all, with a
   known-good GET control before and after the silences. Product finding for a developer
   (RFC 3416 §4.2.2 requires the varbind back with `endOfMibView`), not a process problem.

## Next run: scripts

Existing, all three written during this case and already documented in `tools/README.md`:

- **`tools/snmpq.py`** (README §`snmpq.py`, line 820) --
  `snmpq.py get|getnext|walk|set <agent> <oid>... --v3 --user U --level authPriv --auth-proto
  MD5 --auth-pass P --priv-proto DES --priv-pass P [--expect VALUE|NOSUCH|DENIED|AUTHFAIL|
  TIMEOUT] [--repeat N --interval S] [--timeout S] [--retries N]`. Exit codes 0-6 are the
  grade; `--expect` prints `GRADE PASS/FAIL`. Do not hand-roll `snmpget` again.
- **`tools/snmpwire.py`** (README line 852) -- `snmpwire.py <file.pcap> [--oids] [--port N]
  [--limit N]`. Decodes pcap itself, no dependencies; prints PLAINTEXT vs ENCRYPTED per message.
- **`tools/ckcase.py`** (README line 425) -- `ckcase.py AWPTCM-T43870`, run on a testbox. This
  case's full authored procedure came from `zephyr_cases`; memory
  `ckdb-case-lookup-by-title` says AWPTCM ids are absent from ck.db, and the README entry
  records that this is now out of date. Run it before designing any step from scratch.

Proposed, with the arguments they would take (not built -- the saving is listed, not claimed):

- **`snmpq.py --profile <name>` / `--creds-file <path>`**, reading a small INI or JSON of
  `user/level/auth-proto/auth-pass/priv-proto/priv-pass`, written once per case into `work/`
  by the tester. Removes all 17 re-typings of the credential block and, more importantly,
  removes 16 chances to mangle a password containing `!`, `$`, a backtick or a backslash
  on its way through a local shell, ssh and a remote shell. The README already names the
  alternative (net-snmp `SNMPCONFPATH` + `defAuthPassphrase`) for a password that must never
  appear in an argument list at all.
- **`snmpq.py --save <file>`** -- tee the raw query output to a file under `work/` *and* print
  only the `RESULT`/`GRADE` lines, so a walk's full dump is kept without the `> file; grep`
  pairing the tester hand-wrote 11 times.
- **`tb cfgcheck <box> <sess> <uN> <baud> <logfile>`**, or simply making `tools/tb cfg` exit
  non-zero and print the offending lines when its captured output contains `^% ` or
  `Invalid input` -- the gate memory `bench-scripts-stop-on-cli-errors` asks for. It would have
  caught #66 inside the call that made the mistake and saved #67 and #68.
- **`tb capture` should fetch and chown by default**, or grow a `--fetch <dir>` argument, so a
  pcap lands in `work/` instead of in the box's tmpfs (accuracy risk 3).
