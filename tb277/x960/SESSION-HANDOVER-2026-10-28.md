## Findings

### Measured

**T9032 EAP-TLS — the 2026-10-23 diagnosis was wrong, and the correction is the valuable part.**

| leg | credential | supplicant TLS | client flight | result |
| --- | --- | --- | --- | --- |
| R2-A | whole PKCS#12 | 1.3 | 2141 B, 2 frags | timeout (reproduced to the byte) |
| R2-B | leaf-only + `ca_cert` | 1.3 | **2141 B, 2 frags** | timeout |
| R2-C | leaf-only, no `ca_cert` | 1.3 | 1262 B, 1 frag | timeout |
| R2-D | leaf-only + `ca_cert` | **1.2** | 2154 B, 2 frags | **EAP-Success 1.047 s, Authorized** |
| R2-E | control, rogue cert | 1.2 | 1239 B | **EAP-Failure 1.036 s, Held** |

- A leaf-only `client_cert` alone does nothing: **OpenSSL rebuilds the chain from the verify
  store**, and `ca_cert` is what puts the CA there.
- **Fragmentation was never the cause.** The successful leg carried a two-fragment flight.
- The blocker was **TLS 1.3 alone**: its RFC 9190 commitment message is discarded by
  wpa_supplicant 2.6. Arithmetic closes exactly: 2141 − 1262 = 879 = the CA's 874 DER bytes + 5
  of TLS framing.
- **Fixed with no root** — a per-process `OPENSSL_CONF` (`MaxProtocol = TLSv1.2`), via a new
  `--env` on `tools/wpasup.py`.

**T44287 secure mode — four product deviations worth a developer:**
1. **CR-84010 is not implemented** — the telnet **client** still runs in secure mode.
2. **Secure mode is stricter than its documentation**: **SHA-1 is refused for SNMPv3**, not just
   MD5/DES, so a conforming `auth sha` user built per the wiki is **silently deleted at the next
   restart**.
3. **The CLI help surface reflects no restriction at all** — every probed prefix returns
   byte-identical completions in both modes, and the parser then rejects what the help offered.
4. **Neither documented route to the cryptographic self-test exists**:
   `crypto secure-mode-selftest` is `% Unrecognized command` **in secure mode too**, and
   `show post` adds a `SECURE-MODE POST` heading with nothing under it.

Plus one benign and useful: **a secure-mode round trip deletes a PKI enrolment that no CLI can
remove**, while the trustpoint and its chains return intact.

Product detail is in `platforms/x960.md` §7K.

## OPEN

1. **`tools/snmpq.py` can report success on a net-snmp usage error.** Given `--auth-proto
   SHA-256` it let net-snmp reject the flag, parsed a line out of the resulting **usage dump**,
   and returned `RESULT VALUE` with **exit 0**. Any case passing a protocol name the local
   net-snmp does not know can record a **false PASS**. This run was not misled. Fix: check the
   child's exit status before parsing, and validate `--auth-proto`/`--priv-proto` against what
   the local net-snmp accepts. **This is the one open item that can change a future verdict.**
2. **`tools/case_tokens.py` does not match the `AWPTCM-` prefix** the testers actually write
   (`result_re()` matches `^RESULT T?<id> `), so `--find` returns empty per-case rows. One regex.
3. **tb277 cannot drive an SNMPv3 GET against a secure-mode DUT at all.** net-snmp is 5.7.3
   (`-a` accepts only `MD5|SHA`) and pysnmp's hlapi will not load
   (`Cannot load native module 'Cryptodome.Cipher._raw_ecb'`). Both fixes need root, so they are
   the Test Engineer's. Graded NOT RUN with that reason — an instrument limit, not a DUT result.
4. **EAP-TLS over TLS 1.3 is still not measurable on tb277.** Needs `wpa_supplicant` 2.10+, a
   root install. A separate case if wanted, not a gap in T9032.
5. **The one-console `bench-state.md` clobber** (above). A probe fix would end the manual revert.
6. **T44287's final log grades one step FAIL under an overall PASS case** — N13's
