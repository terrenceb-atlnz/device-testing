Terrence recabled and added an x230-10GP; this records what was actually found
(LLDP-verified, not assumed) and what was changed to make it work **without any
further recabling**, as instructed.

**The x230 console is 9600 baud, not 115200.** Every other console on this bench
is 115200. A driver tuned for 115200 mis-sequences its login.

## Cabling as FOUND (LLDP-verified — this differed from the description)

- TB `eth1` → x230 `port1.0.1`
- x230 `port1.0.2` → **AR4050S `port1.0.2`**
- x230 `port1.0.3` → **IE520 stack `port1.0.2`**

`4050 port1.0.2` and `stack port1.0.2` were the two ends of the SAME LAG member,
so **the x230 had been spliced into the middle of one aggregate link**, creating a
second L2 path between the 4050 and the stack with RSTP disabled on all three.

**Port-naming gotcha that explains it:** on the IE520-28GSX, `portN.0.1` is an
**empty SFP cage** (`show interface status` reads `not present`). The first COPPER
port is `portN.0.2`. So "u2 port1" lands on `port1.0.2`, which was already a LAG
member. Each IE520 member has effectively ONE usable copper port (`portN.0.2`);
everything else is an unpopulated SFP cage.

## Changes made (config only, no recabling)

1. **x230 `port1.0.2` → `shutdown`.** Kills the second 4050↔stack path. The loop is
   now removed deliberately instead of being latent behind an unformed LACP group.
2. **`no lacp global-passive-mode enable` on the stack.** Required: with it on, the
   moment `port1.0.2` left `po1` it auto-rejoined as `channel-group 2 mode passive`,
   and `switchport atmf-link` is rejected on an aggregator member. This is a change
   from the documented baseline and is deliberate — passive LACP fights this design.
3. **Stack `port1.0.2`** removed from `po1` and made `switchport atmf-link`
   (native vlan 1). Note the ordering trap: `no channel-group` is refused while the
   aggregator carries an ATMF link — `no switchport atmf-link` on `po1` first, free
   the port, then re-apply atmf-link to `po1`.
4. **x230:** `atmf network-name tb470`; `port1.0.3` → `switchport atmf-link`,
   `switchport trunk native vlan 100`. Native-vlan bridging (x230 vlan100 untagged
   ↔ stack vlan1 untagged) is what restores TB eth1's data path.
5. x230 `lldp run` enabled (it was off; that is how the cabling was identified).

## Other bench facts confirmed today

- **USB stick present on stack member 1** — 28.9 G, `usbstick … Avail: Y`. Clears
  the hardware blocker on 38475. `dir usb:` from the master fails (master is
  member 3); it needs member-scoped access.
- **The x230 has no AMF licence line** (Base: BASE-AW+, BW-UNLIMITED, IPv6Basic,
  L3-FORWARDING, L3-MC-ROUTE, LAG-FULL, MLDSnoop, No-License-Lock, RADIUS-100,
  RIP, RIPNG, UFO; plus `access`). It joins as a Member anyway — member nodes do
  not need one; the master's AMF-MASTER-250 covers the node count.
- **The x230 was NOT a clean spare.** It arrived with all ports untagged in vlan
  100, an SVI `10.38.215.2/27`, and `channel-group 1 mode active` on `port1.0.2`
  and `port1.0.4`.
